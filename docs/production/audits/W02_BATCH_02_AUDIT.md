# W02 batch 02 independent OCR identity audit

Date: 2026-09-14. Review lenses: JD player experience, baseball record integrity and Gibs technical QA. The reviewer did not implement the remapping helpers, UI or test harness.

**Verdict: UX-12's bounded identity-repair acceptance passes independent source review, component-browser checks and actual HTTP/database submission. No identity-repair blocker remains. Complete reporting feedback and correction provenance remain open follow-ups; this is not full application or release certification.**

## Findings and required acceptance

| Severity | Reproduction and impact | Required acceptance |
| --- | --- | --- |
| P1 · UX-12 | Import a readable but unmatched batter, then edit the displayed name to a valid roster name. The synthetic `playerId` survives; the W02 server correctly rejects the report, leaving the coach unable to repair identity in review. | A roster selection changes ID and canonical name atomically, preserves every entered stat, clears the unresolved marker and moves field provenance and correction keys to the selected ID. Validate the resulting payload. |
| P1 · related pitching defect | Import an unmatched pitcher, then edit its name in review. In score entry, the pitcher selector separately updates ID and name against the same captured array, so the second update can discard the first. | Both pitching selection paths use one row replacement and preserve innings, counters, role and decisions. |
| P1 · ambiguous automatic identity | Put two players with the same full name, surname/initial or substring on the roster. Existing fuzzy matching chooses the first candidate; merging can silently combine different players' statistics. Unmatched normalized names also merge without evidence of identity. | Ambiguous identities remain separate unresolved rows. Deduplication requires a uniquely identified roster player. A coach can deliberately select the correct player and remove a duplicate screenshot row. |
| P1 · discarded pitching data | Supply a pitcher row without a readable name. Extraction filters it out, losing its innings and counters before review. | Preserve unnamed pitching rows and require explicit roster resolution. |
| P2 · ineffective review gate | Unreadable batter names produce only an acknowledgeable warning; readable unmatched names and duplicate IDs produce no identity issue. | Missing, foreign, unresolved and duplicate IDs are hard errors against the relevant team's roster, for batting and pitching separately. Two-way players remain allowed across the two sections. Submission handlers enforce the same gate as the button. |
| P2 · stale correction provenance | Correct the same OCR field twice, remap its player or remove the row. Existing correction logic stops tracking after its provenance becomes `corrected`; identity-keyed metadata can remain attached to the previous ID or deleted row. | Keep the original OCR observation and latest coach value; move associated keys on reassignment and prune removed rows. Do not represent this client bookkeeping as an immutable server audit trail. |
| P2 · reporting feedback | Server validation returns field-addressed issues, but the report form shows only the first message in a transient toast. A roster fetch failure is not clearly distinguished from an empty roster. | Show actionable errors while retaining the draft, and prevent unresolved roster data from being treated as valid identity evidence. |

The identity and pitching defects above are resolved within this batch. Review selectors use canonical roster options, avoid already-used IDs in the same section, allow a player to bat and pitch, and present unresolved rows as unassigned. The parent page uses one reassignment callback for both review and the score-step pitcher selector. Submission checks roster availability and hard identity issues; its handler enforces the gate directly. Extra hard issues are included in the visible OCR review summary. A review row can be removed deliberately without erasing another row's retained identity metadata.

The bounded provenance fix migrates field metadata and existing corrections, preserves an old ID still used by a legacy duplicate, discards stale destination keys and retains the latest repeated edit in OCR review. The broader provenance requirement is **partial**, as detailed below. Both POST and PATCH errors now remain visible in the form while retaining its state, but the richer structured issue display is **partial**.

## Verification

The reviewer independently ran the affected Playwright pure suites. [OCR batting merge tests](../../../tests/unit/ocrBattingMerge.test.ts) passed **8/8**, [roster identity tests](../../../tests/unit/reportRosterIdentity.test.ts) passed **9/9**, and [pitching extraction tests](../../../tests/unit/reportPitching.test.ts) passed **2/2**, all exit 0. The first invocation of the merge and identity filenames selected only the eight merge tests because the new test filename was not yet in the configuration; the nine identity tests were then run after configuration inclusion. No omitted test is counted as a pass.

These tests cover ambiguous exact, surname/initial and substring candidates, preservation of unmatched rows, deterministic matched-player overlap, immutable stat-preserving reassignment, field-key prefix isolation, two-way players, duplicate and foreign selections, repairing pre-existing duplicate IDs, repeated reassignment and already-selected identities. A nine-batter remapped fixture passes the actual server's pure shape/stat validator. That fixture separately checks the client roster list; it does not claim database-backed membership verification.

Independent review caught a new surname-only ambiguity case during implementation: OCR `Smith` with Alex Smith and Sam Smith used the surname's `S` as a given-name initial. The matcher now requires a separate name token before using initial disambiguation, and the passing merge suite includes that adversarial case.

The reviewer independently ran `node --import tsx scripts/verify-ocr-review.ts`: **45 assertions passed**, exit 0, using the installed Edge browser in a fresh headless context at a 375-pixel viewport. The [browser harness](../../../scripts/verify-ocr-review.ts) mounts the actual OCR review component with synthetic state. It checks four unresolved batting/pitching rows, native keyboard roster selection and focus retention, canonical ID/name changes, preserved batting counts and every entered pitching stat/role/decision, metadata movement, duplicate option exclusion, two-way eligibility, hard-issue clearance and the removal callback. It recorded no page errors or external requests and cleaned its owned browser, loopback server and generated bundle directory.

The reviewer independently ran `node --import tsx scripts/verify-reported-results.ts`: **83 assertions passed**, exit 0, against an owned random loopback PostgreSQL database. The [actual HTTP harness](../../../scripts/verify-reported-results.ts) now applies the real client reassignment helper to a synthetic unmatched batting row using the database's roster. The helper's output preserves the extracted counts and is accepted by the actual report submission route and database roster validation; existing confirmation/finalization checks continue to verify mapped season lines. The full invalid-input and no-write rejection checks still pass. The harness removed its owned database and HTTP child; the parent retains responsibility for shutting down the shared test cluster.

Source integration review additionally covered parent-page correction migration, error persistence, score-step pitching reassignment and submission guards. The browser fixture supplies its own state callbacks, so it does not execute those parent-page callbacks. Their current evidence is source review plus the separate helper and HTTP gates, not a complete browser submission journey.

## Acceptance boundaries

This audit concerns repairable identity and report feedback. It does not certify OCR recognition accuracy, complete Power Pros rules, draft recovery, immutable correction history, player enjoyment or an entire season. Current-team membership is not a historical roster revision. Server validation remains authoritative.

The complete-media client build and complete application browser rehearsal remain separate release gates. An isolated browser fixture, if run, must be identified as such; synthetic data and selected components do not establish the full application route, authenticated submission or production assets.

Remaining follow-ups for the central tracker:

- **P2, reporting feedback:** render all relevant structured server validation issues with useful field/section labels. Current first-message persistence reduces lost feedback but does not meet complete feedback acceptance. Existing minimum-row, score and box-score requirements remain application behavior awaiting the league policy contract.
- **P2, correction provenance:** generic score-step stat edits and removals can bypass OCR review correction tracking/pruning. Reproduce by correcting an OCR field in review, returning to score entry, changing or removing the row, then comparing the submitted correction metadata with the final report. Acceptance requires a shared state/update path and regression coverage across both steps, plus W03's separate immutable server revision work.
- **Full application browser gate:** verify route loading, roster failures and recovery, transitions back to score entry, persistent server errors and submitted payloads in the complete client build. The isolated component has no production CSS/media, so its 375-pixel interaction checks are not mobile layout or visual-quality certification.
